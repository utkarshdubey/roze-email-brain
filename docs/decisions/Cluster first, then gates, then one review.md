# Cluster first, then gates, then one review

A flat map/reduce over all cards produced 0/10 acceptable projects in two audits: it merged unrelated
efforts, borrowed aliases, and promoted purchases. So: deterministic entity, domain, and topic clusters;
one bounded enum-cited judgment per cluster; deterministic gates that veto what the model gets wrong.
Oversized clusters split by year before judgment, retaining old efforts without widening a request.
Per-cluster judging then fragmented one effort into pieces and could not see receipts from unread senders,
so one review call per list sees everything the gates accepted, with enumerated, code-checked verdicts and
enum-bound evidence, and the result passes the gates again. Both changes were made against measurements
([[Evaluation]]). Related: [[Concept layer]], [[Topics are the third cluster family]],
[[Bodies before concepts]].
